Chapter 1

Executive Summary & Problem Statement

1.1 The Campus Property Crisis

Across contemporary collegiate environments, personal belongings worth hundreds of thousands of dollars—including high-end laptops, smartphones, state IDs, laboratory notebooks, and transit passes—disappear every semester. Traditional recovery methods are universally fractured, inefficient, and insecure:

  • Informal Social Feeds: Unvetted posts on WhatsApp groups, Telegram channels, and Facebook communities suffer from near-instant message decay and lack persistent searchability.
  • The "Black Box" Lost Desk: Campus physical lost boxes are analog, uncatalogued, and completely opaque. Students must physically walk across campus during restrictive office hours to search through crates of lost items.
  • High Fraud & False-Claim Vulnerability: When an expensive device (e.g., Apple MacBook or iPad) is announced on social media, malicious individuals claim ownership by simply bluffing details, forcing university security desks to accept unverified liability.
  • Cloud-AI Overdependence & Fragility: Most modern software prototypes hastily wrap a proprietary LLM API (e.g., OpenAI/Gemini) without consideration for latency, cost, privacy, or server availability. When the cloud API rate-limits or Wi-Fi drops, the entire platform collapses.

1.2 The ReFind Solution

ReFind is an enterprise-grade, campus-scale asset recovery platform engineered to eliminate these pain points. Built with a zero-build-overhead philosophy, it introduces an explainable, multi-signal matching engine, zero-knowledge cryptographic ownership verification, real-time in-browser computer vision, and a legally defensible chain of custody with verifiable physical printables.

2.2 Complete Report-to-Recovery Data Flow

  1. Report Registration: A student reports a lost or found item. If an image is attached, the client-side canvas extracts its dominant color in real time.
  2. Asynchronous Match Generation: The server executes the 100-point matching engine against all active counterpart items. Matches scoring ≥ 55% generate immediate in-app notifications.
  3. Ownership Challenge: When claiming a found item, the claimant must answer the private challenge set by the finder. The submitted plaintext is converted to a SHA-256 digest and compared to the stored hash.
  4. Triage & Approval: Exact matches auto-approve; ambiguous or unverified claims route to the Admin Manual Review Queue with confidence scores, phone numbers, and photo ID proofs.
  5. Public Catalog De-Listing: Upon claim approval, both the found item and the claimant's matching lost item are instantly hidden from the public item browser.
  6. Custody Release & Legal Receipt: The admin hands over the physical property, generating a serialized Custody Release Receipt with QR verification and signature panels, concluding the audit log.
Chapter 3

The 100-Point Hybrid Matching Engine

3.1 The Mathematical Formulation

ReFind rejects opaque black-box AI by combining deterministic structured features with contextual semantic intelligence. Every comparison between a lost item $L$ and a found item $F$ is governed by a bounded scoring function:

$$\text{Score}(L, F) = W_{\text{cat}} \cdot S_{\text{cat}} + W_{\text{col}} \cdot S_{\text{col}} + W_{\text{loc}} \cdot S_{\text{loc}} + W_{\text{time}} \cdot S_{\text{time}} + W_{\text{ai}} \cdot S_{\text{ai}}$$

Where the weights are fixed constants summing to 100:

  WEIGHTS = {
    category: 25,  // Macro classification
    color:    15,  // Chromatic feature
    location: 20,  // Spatial proximity
    time:     15,  // Temporal decay
    ai:       25   // Semantic free-text nuance
  };

3.2 Deep Dive into Scoring Components

1. Category Similarity ($S_{\text{cat}} \in [0, 1]$ — Max 25 Points)

Category represents the highest information gain. Exact matches yield $1.0$ ($25$ pts). To account for subjective human classification (e.g., whether a laptop case is an "accessory" or a "bag"), ReFind defines a bidirectional related-category graph: 

const RELATED_CATEGORIES = {
  electronics: ['accessories'],
  bags:        ['accessories'],
  accessories: ['electronics', 'bags', 'jewelry'],
  documents:   ['cards'],
  cards:       ['documents'],
  clothing:    ['accessories']
};

Pairs present in this adjacency list receive a partial credit multiplier of $0.5$ ($12$ pts). Unrelated categories score $0$.

2. Color Family Similarity ($S_{\text{col}} \in [0, 1]$ — Max 15 Points)

Because lighting variations cause human perception errors (e.g., navy blue appearing black), color is scored using chromatic clustering. An exact string match yields $1.0$ ($15$ pts). Membership in the same perceptual color family (e.g., ['black', 'dark', 'charcoal', 'navy']) yields $0.6$ ($9$ pts).

3. Spatial Proximity & Canonical Normalization ($S_{\text{loc}} \in [0, 1]$ — Max 20 Points)

Campus geography is represented as a spatial adjacency graph. Prior to scoring, informal campus vernacular and abbreviations are normalized using an alias table: 

LOCATION_ALIASES: {
  'lib'        -> 'central library',
  'cs building'-> 'computer science building',
  'canteen'    -> 'cafeteria',
  'audi'       -> 'auditorium'
}

Exact matches score $1.0$ ($20$ pts). Locations verified as adjacent in the campus topology (e.g., Central Library $\leftrightarrow$ Computer Science Building) receive partial credit of $0.5$ ($10$ pts).

4. Temporal Exponential Decay ($S_{\text{time}} \in [0, 1]$ — Max 15 Points)

The temporal delta $\Delta t = |t_{\text{lost}} - t_{\text{found}}|$ is evaluated using an exponential decay function. Reports within 24 hours score full credit ($15$ pts). Between 24–72 hours, it yields $10$ pts; between 3–7 days, $6$ pts; beyond 7 days, it decays progressively towards 0.

5. Semantic AI Similarity & Local Fallback ($S_{\text{ai}} \in [0, 1]$ — Max 25 Points)

Free-text descriptions are passed to Google Gemini with strict JSON-schema enforcement to extract fine-grained attributes (e.g., scratches, stickers, brand models). The returned 0–100 similarity score is scaled to 25 points.

Zero-Failure Fallback Guarantee: If the Gemini API key is unconfigured, rate-limited, or unavailable, aiService.js automatically triggers a local, zero-cost synonym clustering algorithm. The system continues to operate 100% offline without dropping exceptions or stalling the user experience.
Chapter 4

Zero-Knowledge Verification & Anti-Fraud Security

4.1 The Security Vulnerability of Open Lost & Found Portals

In conventional lost-and-found software, found item descriptions are completely public. Anyone can browse the portal, view the exact description of an expensive camera or wallet, approach the security desk, and falsely claim it. ReFind eliminates this through Zero-Knowledge Ownership Verification.

4.2 The SHA-256 Challenge Protocol

  1. Secret Setup: When reporting a found item, the finder provides a secret question and answer (e.g., "What is the engraving on the watch buckle?" $\rightarrow$ "Initials J.R. 2022").
  2. One-Way Hashing: The server computes $H = \text{SHA-256}(\text{normalize}(\text{Answer}))$ and stores only $H$. The plaintext answer is permanently discarded from memory.
  3. API Isolation: Public item endpoints strip all verification fields. Only the question text is exposed to authenticated users initiating a claim.
  4. Claim Verification: The claimant submits their answer. The server hashes the submission and verifies $H_{\text{submitted}} == H_{\text{stored}}$.
  5. Anti-Brute-Force Lockout: To prevent dictionary attacks against the secret question, ReFind tracks failed attempts in verification_attempts. Three consecutive failed attempts trigger an automatic 15-minute cooldown.
Chapter 5

Client-Side Computer Vision & Color Extraction

5.1 Zero-Cost In-Browser Computer Vision

Rather than uploading multi-megabyte images to an expensive server-side computer vision microservice, ReFind executes dominant color extraction entirely on the client’s browser using HTML5 Canvas pixel parsing in public/js/color-extractor.js.

5.2 The HSL Pixel Classification Pipeline

  1. Downsampling: The uploaded image is drawn onto an offscreen canvas downscaled to $100 \times 100$ pixels (10,000 sampling points), eliminating latency.
  2. RGB to HSL Transformation: Each pixel is converted from RGB to the Cylindrical HSL (Hue, Saturation, Lightness) color space.
  3. Achromatic & Chromatic Thresholding:
    • Pixels with Lightness $L < 0.16$ are classified as Black.
    • Pixels with Lightness $L > 0.88$ and Saturation $S < 0.20$ are classified as White.
    • Pixels with Saturation $S < 0.15$ are classified as Gray or Silver depending on $L$.
    • Chromatic pixels are mapped across 18 color bins based on circular Hue degrees ($0^\circ \dots 360^\circ$).
  4. UI Chip Auto-Population: The top 3 dominant colors are presented to the user as clickable palette chips, automatically pre-filling the structured color field.
Chapter 6

Auditable Chain-of-Custody & Printable Artifacts

6.1 Official Custody Release Receipts (public/receipt.html)

When a student picks up an approved item from the campus security desk, ReFind generates an official, printable Custody Release Receipt. This establishes a legally binding audit trail protecting the university from property disputes.

  • Serialized Receipt Number: Unique identifier formatted as REC-XXXXX.
  • Cryptographic QR Verification: Embedded SVG vector QR code deep-linking directly to the encrypted database record.
  • Claimant Verification Metadata: Details student ID, full legal name, phone number, and confidence score.
  • Dual Signature Panels: Formal physical signature blocks for both the releasing security officer and the receiving student.

6.2 Physical Bulletin Flyers (public/flyer.html)

Digital tools must bridge to the physical world. For urgent lost items, ReFind generates a high-resolution, printable A4 bulletin flyer featuring a high-contrast item photo, vital metadata, and a high-resolution scan-to-claim QR code for campus noticeboards.

The team is prepared to defend every architectural choice: Why SQLite? Eliminates external daemon overhead, delivers sub-5ms local queries, and provides ACID compliance. Why not 100% LLM? ReFind's hybrid engine isolates AI to a 25-point accelerator slice while keeping the system 100% operational offline.

Features a bespoke typography system (Newsreader + Work Sans), dark/light mode with full token parity, interactive SVG campus maps, real-time audio synthesis (Web Audio API), and pixel-perfect printable receipts and flyers.

5. Feasibility of the Project (10%)

Production-ready today. Zero build steps, runs on any standard Node 22+ runtime, auto-initializes schemas, and integrates cleanly with campus LDAP/SSO or standalone intranet environments.

6. Cost of Implementation (10%)

7. Challenges in Implementation (10%)
